# 考试模式三阶段设计（已定稿）

> 范围：`badminton-teacher` 教师端 + `relay-server` + `gym_screen`，并约定需管理后台 `admin-api` / 算法服务配合的接口。  
> 顺序：**建考配置 → 考场大屏协同 → 视频分析与结果闭环**；每阶段可独立验收后再进入下一阶段。  
> 依据：课内需求/概要/详细设计、考试端流程图、现有考核页与中继协议。  
> **审核结论（2026-08-12）**：见 §6；下文已按结论改写，可据此开工。

---

## 0. 目标与原则

### 0.1 产品目标（对齐流程图）

1. **创建考试**：关联考试课堂；配置本场考试成绩占比、考核项与教学资料；同课程多场考试占比之和 ≤ 100%。  
2. **进入考试**：选考试课堂 → 连接大屏；开考前大屏展示考核项并播放资料；开考后大屏按序展示待考学员。  
3. **考后分析**：学员考核视频进入分析队列；完成后只保留分析结果、删除原视频；教师手机可查看结果。

### 0.2 设计原则

| 原则 | 说明 |
|------|------|
| 复用现有上课遥控链路 | 大屏仍经 `relay-server`（WS + `/media-proxy`），避免另起通道 |
| 考试与上课状态隔离 | `SessionState` 增加 `mode`；考试态收到 `setPlan` **拒绝**（`mode_conflict`） |
| 先配置后现场 | 阶段 1 不依赖大屏；阶段 2 不依赖算法闭环；阶段 3 再接分析与成绩 |
| 后端契约先行 | 每阶段先定 API / 表字段增量，前端按契约 Mock 或联调 |
| 最小改动现有上课功能 | 上课 `screen-control` 路径保持可用；考试另开页面 |
| 算法不直连小程序 | 阶段三起教师端**禁止**直连算法服务 IP，一律经 `admin-api` |

### 0.3 现状基线（不重复开发）

已有：班级详情「考试」入口、`lesson-list?forExam=1`、`exam-setup` / `exam-session` / `exam-active` 壳子、动作识别视频上传试点、`setPlan` 训练大屏协议。

将演进为：真正的「考试头表 + 考核项配置」→「考试大屏两阶段展示」→「成绩/结果闭环」。旧的「前端写死场地 + 算法类型二选一」逐步被配置数据替代；场地摄像头落点能力放在阶段 3 可选增量，不阻塞主路径。阶段一/二若仍残留直连算法试点代码，阶段三合并时删除。

## 1. 阶段一：建考配置

### 1.1 用户故事

教师在课程下创建一场考试：选择/创建**考试课堂**（`lesson.type = 2`），写入独立 **`teaching_exam` 头表**（含本场成绩占比），配置若干**考核项**（含满分/项内权重/算法类型），并为考核项挂**教学资料**（新表）。保存时校验同课程已有考试占比之和 ≤ 100%。

### 1.2 信息架构与页面

| 页面（建议路径） | 职责 | 相对现状 |
|------------------|------|----------|
| `pages/exam-list/exam-list` | 某课程下考试列表（按 `teaching_exam`），展示占比、状态 | **新建** |
| `pages/exam-create/exam-create` | 创建/编辑考试：关联考试课堂、占比、标题等 | **新建** |
| `pages/exam-items/exam-items` | 考核项列表与排序（按 `examId`） | **新建** |
| `pages/exam-item-edit/exam-item-edit` | 单项：名称、满分、权重、算法类型、资料 | **新建**（上传可复用现有 upload 能力，元数据写入新表） |
| `pages/lesson-create` | 类型选项增加「考试课堂」 | **改** |
| `pages/class-detail` | 「考试」进入 `exam-list` | **改入口** |

建议入口：

```text
首页选班级 → 班级详情 → 考试
  → 考试列表（本课程 teaching_exam）
     → 新建考试 / 编辑配置
     → 进入考场（阶段二，配置未完成则拦截）
```

### 1.3 数据模型增量

#### 1.3.1 已有表（直接使用）

- `teaching_lesson`：`type = 2` 表示考试课堂；`course_id`、`week_index`、时间字段沿用。  
- `teaching_exam_item`：演进为挂在 **`exam_id`**（见下）；保留/迁移原 `lesson_id` 语义。  
- `teaching_course.exam_weight`：考试块占总评权重（默认 70），与多场占比合成见 §1.3.3。

#### 1.3.2 已定：独立考试头表 `teaching_exam`

**不在 `teaching_lesson` 上挂占比。** 每场考试一行头表，与考试课堂 **1 : 1**。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `bigint` PK | 考试 ID |
| `course_id` | `bigint` | 所属课程 |
| `lesson_id` | `bigint` UK | 关联 `teaching_lesson.id`（须 `type=2`） |
| `title` | `varchar(128)` | 考试标题（可默认「第 N 周考试」） |
| `score_ratio` | `int` | 本场在「考试块内」占比，1–100 |
| `status` | `tinyint` | `0` 配置中 / `1` 可开考 / `2` 进行中 / `3` 已结束（可选，前端可先只用 0/1） |
| `creator` / `create_time` / `updater` / `update_time` / `deleted` / `tenant_id` | | 与现有表一致 |

校验（服务端强制，前端提示）：

- 同 `course_id` 下未删除考试的 `score_ratio` **之和 ≤ 100**。  
- `lesson_id` 必须存在且 `type=2`，且未被其他考试占用。

#### 1.3.3 考核项与资料（已定）

**`teaching_exam_item` 增量 / 调整**

| 字段 | 类型 | 说明 |
|------|------|------|
| `exam_id` | `bigint` | **必填**，关联 `teaching_exam.id`（主键关联；`lesson_id` 可冗余便于查询或逐步废弃） |
| `item_name` | `varchar(100)` | 如发球 / 高远球 |
| `max_score` | `int` | 项目满分 |
| `weight` | `int` | 项内权重（百分比） |
| `algo_type` | `tinyint` | `1` 动作识别，`2` 落点检测 |
| `sort_order` | `int` | 展示与考试顺序 |

项内 `weight`：同一 `exam_id` 下各项之和 **= 100**（服务端校验）。

**资料：新表 `teaching_exam_item_material`（已定 C1）**

结构对齐 `teaching_item_material`，外键改为 `exam_item_id`：

| 字段 | 说明 |
|------|------|
| `id` | PK |
| `exam_item_id` | 关联考核项 |
| `material_type` | `1` 图片 `2` 视频 |
| `image_url` / `video_url` / `duration` / `title` / `description` / `sort` | 同计划资料 |
| 租户与审计字段 | 同现有表 |

上传二进制可复用 `POST /teaching/plan-material/upload`（或新建等价 upload）；**元数据只写入本表**，不写入计划资料表。

#### 1.3.4 与课程 `examWeight` 的合成（已定默认）

- `teaching_course.exam_weight`：总评中「考试块」占比（默认 70）。  
- 各场 `teaching_exam.score_ratio`：考试块**内部**分配，同课程之和 ≤ 100。  
- 某场考试折合总评权重：

```text
场次占总评% = course.exam_weight × (exam.score_ratio / 100)
```

阶段一只实现「多场 `score_ratio` 之和 ≤ 100」校验；上式在成绩汇总/报表迭代使用。

### 1.4 API 契约（admin-api，前缀 `/admin-api`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/teaching/lesson/create` | 已有；考试课堂传 `type: 2`（**不含**占比） |
| GET | `/teaching/lesson/list-by-course` | 支持 `type` 过滤，供选课堂 |
| POST | `/teaching/exam/create` | 创建头表：`courseId`、`lessonId`、`title`、`scoreRatio`；校验占比与 lesson |
| PUT | `/teaching/exam/update` | 更新标题/占比等，重校验之和 |
| DELETE | `/teaching/exam/delete` | 软删头表（策略：级联软删项与资料，或禁止有成绩时删除） |
| GET | `/teaching/exam/get` | 详情 |
| GET | `/teaching/exam/list-by-course` | 考试列表（含占比、关联课堂周次） |
| POST | `/teaching/exam-item/create` | `examId` + 项字段 |
| PUT | `/teaching/exam-item/update` | 更新 |
| DELETE | `/teaching/exam-item/delete` | 软删 |
| GET | `/teaching/exam-item/list-by-exam` | 按考试列项 |
| POST/PUT/DELETE/GET | `/teaching/exam-item-material/*` | 考核项资料 CRUD；上传可共用现有文件接口 |

权重校验错误码：`exam_ratio_exceeded`，`msg` 含「已占用 x%，剩余 y%」。

### 1.5 教师端交互要点

- 新建考试：先选/建 `type=2` 课堂 → 填头表 `scoreRatio`（展示「已用/剩余」）→ 保存 `teaching_exam` → 编辑考核项。  
- 考核项至少 1 条才允许「进入考场」。  
- 教学资料**选填**（阶段一不强制每项都有资料；阶段二播片再依赖 URL）。  
- `lesson-create` 的 `typeOptions` 为 `['普通课堂','考试课堂']`；提交时 `type` 必须 `Number()`，避免 picker 字符串拼接成 `11`。

## 2. 阶段二：考场大屏协同

### 2.1 用户故事

教师选择已配置完成的考试（`teaching_exam`），手机连接大屏中继。  
**开考前**：大屏展示本场考核项列表，并播放当前项教学资料（复用 media-proxy）。  
点击**开始考试**后：大屏切换为「学员队列 + 当前考生」视图，按教师端指定顺序展示。

### 2.2 流程

```text
考试列表 → 进入考场（exam-room）
  → 连接 relay（同 screen-control：roomId/token）
  → 下发 setExamBriefing（考核项 + 资料 URL + mediaBearerToken）
  → 大屏 briefing 视图：项列表 + 播片
  → 教师「开始考试」→ startExam(examinees[])
  → 大屏 running 视图：当前学员高亮，其余排队
  → 教师切换下一名 → setCurrentExaminee / advanceExaminee
  → （阶段三）对当前学员发起采集/上传
```

与现有考核流衔接：

- `exam-setup` 写死场地/算法二选一：**降级为可选元数据或移除**，不阻塞大屏主路径；算法类型以考核项 `algo_type` 为准。  
- 学员列表：`GET /teaching/class-student/list-by-class`；默认名册序，支持调整后下发。

### 2.3 中继协议扩展（`relay-server`）

#### 2.3.1 `SessionState` 增量

```ts
type ExamPhase = 'idle' | 'briefing' | 'running' | 'finished'

type ExamItemView = {
  id: string
  title: string
  maxScore?: number
  weight?: number
  algoType?: number
  videoUrl?: string
  imageUrl?: string
  instruction?: string
}

type ExamineeView = {
  classStudentId: string
  userId?: string
  name: string
  studentNo?: string
  status: 'waiting' | 'testing' | 'done'
}

// SessionState 增加：
mode: 'training' | 'exam'   // 默认 training
examPhase: ExamPhase
examTitle?: string
examId?: string            // 对应 teaching_exam.id，便于对账
examItems: ExamItemView[]
currentExamItemId: string
examinees: ExamineeView[]
currentExamineeId: string  // classStudentId
```

#### 2.3.2 考试态与 `setPlan`（已定：拒绝）

当 `mode === 'exam'` 时收到 `setPlan`（以及其它纯训练命令，建议同样拒绝）：

- **不**切回 training、**不**改考试字段  
- 向发起端回 `{ type: 'error', code: 'mode_conflict', message: '当前为考试模式，请先结束考试' }`  
- 大屏状态不变  

退出考试：仅 `exitExamMode` / `finishExam` 后允许再 `setPlan`。

#### 2.3.3 新命令

| name | payload 要点 | 效果 |
|------|----------------|------|
| `setExamBriefing` | `{ examId?, examTitle, items[], currentItemId?, mediaBearerToken?, mediaTenantId? }` | `mode=exam`, `examPhase=briefing` |
| `setExamItem` | `{ id }` | briefing 下切换当前资料项 |
| `setExamVideoPlaying` | `{ playing }` | 控制 briefing 播片 |
| `startExam` | `{ examinees[], currentExamineeId? }` | `examPhase=running`；建议停播 |
| `setCurrentExaminee` | `{ classStudentId }` | 更新当前考生与状态 |
| `advanceExaminee` | `{}` | 当前 `done`，下一名 `testing` |
| `finishExam` | `{}` | `examPhase=finished` |
| `exitExamMode` | `{}` | 回到 `mode=training` 初始态 |

`tick`：考试态默认不推进训练用 `sessionElapsedSec`。

### 2.4 `gym_screen` 展示

| `examPhase` | 界面 |
|-------------|------|
| `briefing` | 考核项列表（当前项高亮）+ 视频/图片（`media-proxy`） |

| `finished` | 「本场考试结束」 |

`WorkingStatus.vue` 按 `session.mode` 分支；新建 `ExamBriefing.vue` / `ExamRunning.vue`。

## 3. 阶段三：视频分析与结果闭环

### 3.1 用户故事

学员当场考核结束后，教师上传该生该考核项视频 → **经 admin-api** 入队分析 → 回调写结果 → **删除原视频** → 手机查看 AI 初分并可改最终分。

### 3.2 状态机（`teaching_exam_score.status`）

```text
0 待考试 →（提交视频）→ 1 计算中
1 计算中 →（算法成功回调）→ 2 待审核（algo_score 已写，原视频已删）
2 待审核 →（教师确认/改分）→ 3 已完成
1 计算中 →（失败）→ 回 0（或 4 失败）；保留或清理失败视频按后台策略，默认回 0
```

#### 重考策略（已定：覆盖）

UK `(student_id, exam_item_id)`：同一学员同一考核项再次提交 → **覆盖**原成绩行（重置为计算中，清空旧 AI 结果；若旧视频未删则删除后写新 URL）。

### 3.3 表字段增量

已有：`video_url`、`video_duration`、`ai_callback_time`、`algo_score`、`final_score`、`comment`、`status`。

建议增加：`algo_request_id`、`result_json`、`result_summary`、`video_deleted`；并增加 `exam_id` 冗余便于按场查询（若尚无）。

### 3.4 流程与职责

```text
教师端 exam-active
  → 当前考核项 + 当前学员（与大屏一致）
  → 选视频
  → POST /teaching/exam-score/submit-video（仅 admin-api）
  → 后台入队并调用算法（小程序不持有算法 Base URL）
  → 算法回调 admin-api
       → 写结果，status=2，删 OSS 原片
  → 教师 GET 列表/详情 → PUT review → status=3
```

**已定：禁止小程序直连算法 IP。** 删除或停用 `examRecognition.js` 内 `ACTION_RECOGNITION_BASE_URL` 直传逻辑；改为只调 `exam-score` API。阶段一/二遗留试点代码在本阶段清理。

落点检测未就绪时：`algo_type=2` 显示「暂未开放」；MVP 只闭环动作识别。

| PUT | `/teaching/exam-score/review` | 改分、评语、置完成 |

### 3.7 阶段三验收 / 测试

| # | 用例 | 期望 |
|---|------|------|
| 3.1 | 提交动作视频 | `计算中`；抓包确认**无**直连算法 IP |
| 3.2 | 回调成功 | 有 `algo_score`，`待审核`，原视频已删 |

## 6. 审核结论（已锁定）

| # | 议题 | 结论 |
|---|------|------|
| 1 | 本场占比存放 | **独立头表 `teaching_exam`**（`lesson_id` 1:1，`score_ratio`） |
| 2 | 与 `course.exam_weight` | **默认**：多场 `score_ratio` 之和 ≤100%，场次占总评% = `exam_weight × score_ratio/100` |
| 3 | 资料挂接 | **新表 `teaching_exam_item_material`** |
| 4 | 考试态 `setPlan` | **拒绝**，`error.code = mode_conflict` |
| 5 | 同学员同考核项重考 | **覆盖** |
| 6 | 小程序直连算法 IP | **禁止**；阶段三只走 admin-api |
| 7 | `exam-setup` 场地 | 仍建议可选/移除，不阻塞主路径（未单独反对则按此执行） |
