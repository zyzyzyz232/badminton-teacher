# badminton-teacher 系统出错处理

> 羽毛球教学教师端、relay-server 中继、训练大屏（gym_screen）及 admin-api 的错误/故障一览、输出含义与补救措施。  
> 与 `教学系统详细说明文档.md`、`考试模式旁路后端与联调.md`、`relay-server/DEPLOY.md` 配套使用。

---

## 1. 通用约定

### 1.1 输出形态

| 形态 | 载体 | 说明 |
|------|------|------|
| Toast | 教师端小程序/H5 | `icon: success` 成功；`icon: none` 失败/提示 |
| Modal | 教师端 | 删除确认等二次确认 |
| Loading | 教师端 | 绑定课堂等长操作 |
| `statusLine` | 遥控页顶部状态栏 | WebSocket 连接与房间状态 |
| 调试日志 | 遥控页可折叠面板 | 标签如 `ERROR`/`CONNECT`/`setPlan` |
| HTTP JSON | admin-api | `{ code, msg, data }`，`code === 0` 为成功 |
| WS JSON | relay-server | `joined` / `state` / `error` |
| `lastError` | 大屏顶栏红字 | 中继连接错误，附「重试」按钮 |
| 页面遮罩 | 大屏 TeachingVideo | 「教学内容加载失败」等 |

### 1.2 校验分层

1. **页面级**：Toast 拦截，禁止继续操作  
2. **服务封装级**：`trainingPlanApi.js` / `examApi.js` / `userProfile.js` / `examRecognition.js` 抛 `Error`  
3. **后端/中继级**：HTTP `code≠0`；WS `{ type: 'error', code, message }`

### 1.3 通用恢复原则

| 原则 | 说明 |
|------|------|
| 先判层级 | 区分前端校验、HTTP 后台、中继 WS、大屏媒体哪一层出错 |
| 同机同房间 | 教师端、大屏、中继须连**同一台** `3456`；房间/令牌一致（默认 `1001` / `2002`） |
| 先连后下发 | 遥控页须「已加入房间」后再「刷新计划」；`joined` 后自动 `setMediaAuth` + `setPlan` |
| Token 失效先登出再登 | 大量「请先登录」或 HTTP 失败时，退出后重新登录 |
| 无自动回滚 | 新建训练项目（建项→上传→登记）任一步失败不自动撤销，需人工检查 |

## 2. 认证与登录

| 故障 | 输出形式 | 含义 | 处理方式 |
|------|---------|------|---------|
| 账号/密码为空 | Toast「请输入账号」「请输入密码」 | 前端校验 | 补全后提交 |
| 注册字段不全 | Toast「请输入教师姓名」「请输入手机号」「两次密码不一致」 | 前端校验 | 补全并核对密码 |
| 未登录 | Toast「请先登录」；`ensureTeacherSession` 抛错 | 无 token | 我的 → 退出登录 → 重新登录 |
| 登录响应无令牌 | Toast「登录响应缺少令牌」 | 后台未返回 `accessToken` | 查后台登录接口 |
| 登录/注册业务失败 | Toast `res.data.msg` 或「操作失败」 | `code≠0` | 按 `msg` 修正或联系后台 |
| 网络不可达 | Toast「网络连接异常」 | `uni.request` fail | 检查 `10.112.189.54:48080` 与终端网络 |
| 登录后拉 profile 失败 | Toast `err.message` 或「获取用户信息失败」 | profile 接口异常 | 重登；查 `GET /system/user/profile/get` |
| 无教师 ID | Toast「无法获取教师账号信息」 | `userInfo.id` 无效 | 重登；`ensureTeacherSession` 会尝试再拉 profile |
| H5 误入遥控页 | Toast「请从「选择训练计划」进入遥控」 | 无 `planId` | 自动跳首页/登录（`App.vue`） |

**补救（再启动）**：退出登录清除 `token`/`userInfo` 后 `reLaunch` 登录页；H5 无 token 时 `reLaunch` 到 `pages/index/index`。

## 3. 管理后台 HTTP（admin-api）

### 3.1 公共错误模式

| 故障 | 输出形式 | 含义 | 处理方式 |
|------|---------|------|---------|
| 业务失败 | Toast `msg` 或 `请求失败(code)` | `code≠0` | 按后台 `msg` 处理 |
| 空响应 | `Error('空响应')` → Toast | 网关/服务无 body | 查 admin-api 进程与网关 |
| 网络错误 | Toast「网络连接异常」「网络错误」 | 请求 fail | 检查网络与服务地址 |
| 缺少教师信息 | `Error('缺少教师信息，请重新登录')` | `teacherId≤0` | 重新登录 |

### 3.2 课程与课堂

| 模块 | 故障 | 输出 | 处理 |
|------|------|------|------|
| 首页 | 获取数据失败 | Toast `msg` /「网络连接异常」 | 重进首页；确认已登录 |
| 我的课程 | 字段未填 | Toast「请输入课程名称」等 | 补全表单 |
| 我的课程 | 创建/列表失败 | Toast `msg` /「网络连接异常」 | 重试；查 `teaching_course` 接口 |
| 课堂列表 | 课程ID无效 | Toast | 从正确入口进入 |
| 课堂列表 | 获取/删除失败 | Toast `msg` /「网络连接异常」 | 重进列表重试 |
| 课堂列表 | 课堂数据缺少编号 | Toast | 刷新列表；异常课次删重建 |
| 创建课堂 | 周次/时间未选 | Toast「请选择周次」等 | 补全 picker |
| 创建课堂 | 创建失败 | Toast `msg` /「网络连接异常」 | 重试提交 |
| 班级选择 | 课程ID无效 / 获取失败 | Toast | 返回课程详情重进 |

### 3.3 训练计划与项目

| 模块 | 故障 | 输出 | 处理 |
|------|------|------|------|
| 计划列表 | 列表空/失败 | 空列表 + Toast；或**自动降级** | 主接口失败时用 `plan-project` 聚合；重进 Tab |
| 计划信息 | 标题为空 | `请填写计划标题` | 填写后保存 |
| 计划信息 | 创建/保存失败 | Toast `msg` /「保存失败」 | 重试；查 plan 接口 |
| 计划信息 | 计划 id 无效 | Toast | 先保存再操作 |
| 课中选计划 | 未登录 / 课堂ID无效 | Toast | 登录；从课堂列表进入 |
| 课中选计划 | 获取列表失败 | Toast `err.message` | 检查网络；先在「训练计划」Tab 新建 |
| 课中选计划 | 绑定课堂失败 | Toast「绑定课堂失败」+ message | 确认 `lessonId>0`；重选计划再绑定 |
| 项目编排 | 项目名称为空 / 未选资料 | Toast | 补全后创建 |
| 项目编排 | 创建中途失败 | Toast 具体错误（最长 2.8s） | **无回滚**：检查是否留下半成品项，删或补传 |
| 项目编排 | 创建成功但未返回 id / 上传无地址 | 内部 Error | 查 create/upload 接口返回值 |
| 项目编排 | 移除/删除/排序失败 | Toast `err.message` | 重试对应操作 |
| 项目编辑 | 项目 id 无效 / 加载失败 | Toast | 从列表重新进入 |
| 资料管理 | 参数不完整 | Toast | 确认路由 `planId`、`itemId` |
| 资料管理 | 获取/上传/更新/删除失败 | Toast `msg` 或「网络错误」 | 重选文件重传；查 upload 接口 |

**补救（再启动）**：离开页面再进入触发重新加载；绑定课堂用 Loading「绑定课堂…」失败后可再次确认选择。

### 3.4 考试模式（旁路 48081）

| 故障 | 输出 | 含义 | 处理 |
|------|------|------|------|
| Toast「系统异常」且考试资料表无行 | 旁路 500 | 旧 jar 仍走七牛 `FileApi`（S3 403），或未重启新包 | 停掉 48081 进程 → `mvn -pl yudao-server -am package -DskipTests` → `java -jar yudao-server.jar`；查日志不应再出现 `S3Exception` |
| 创建考试 404 / 空列表 | HTTP | 考试 CRUD 打到了 48080，或旁路未启动 | 确认 `examApi.js` 考试路径走 `TEACHING_API_BASE`（48081）；Redis 与 jar 已起 |
| 拉课堂 404 | HTTP | `list-lessons` 误打 48081 | 课堂列表必须走现网 48080 |
| 考试课堂存成普通课堂 | DB `type=11` 或 `1` | picker 把 `"1"` 当字符串拼接 | 前端 `Number(e.detail.value)`；已脏数据需改 `teaching_lesson.type=2` |
| 上传成功但 Navicat 看不到 | 查错表 | 考试行在 `teaching_exam_item_material` | 不要只看 `teaching_item_material` |
| 占比超限 | Toast 含「剩余」 | 同课程 `score_ratio` 之和 > 100 | 按提示改占比 |
| 进入考场被拦 | Toast | 无考核项，或项内权重未满 100 | 先保存考核项并凑满权重；资料选填 |
| 旁路连不上 | 网络错误 | 本机 IP 变了或防火墙 | 改 `TEACHING_API_BASE`；开发者工具可关闭域名校验 |

**补救**：考试文件优先现网 `plan-material/upload`（`pic-video`）；失败走旁路本地 `file-storage`。详见 `考试模式旁路后端与联调.md`。

## 4. 大屏遥控（WebSocket + 教师端）

### 4.1 教师端前端校验与连接

| 故障 | 输出形式 | 含义 | 处理 |
|------|---------|------|------|
| WS 地址无效 | Toast「WS 地址格式无效」 | URL 格式错误 | 改为 `ws://host:3456` |
| 未填 WS | Toast「请先填写 WS 地址」 | 空地址 | 填写并保存（本地 `relayWs`） |
| 房间/令牌格式错 | Toast「房间号与令牌均为4位数字」 | 非 4 位数字 | 使用 `1001`/`2002` |
| 中继探测失败 | Toast「中继不可达」「无法访问中继」；`relayProbeHint` | HTTP `/relay-info` 不可达 | 启动 relay；查 IP/防火墙 |
| 中继可用 | Toast「中继可用」 | 探测成功 | 继续点「连接」 |
| 无法发起连接 | `statusLine`「无法发起连接」 | `connectSocket` fail | 查 WS 地址与网络 |
| WebSocket 错误 | `statusLine`「WebSocket 错误」 | `onError` | 重点「连接」 |
| 连接已关闭 | `statusLine`「连接已关闭」 | `onClose` | 重点「连接」 |
| 连接已断开（发令时） | `statusLine`「连接已断开」；日志 SEND | 发送时 socket 不可用 | 先连接再加入房间 |
| 未连接大屏 | Toast「未连接大屏」 | `requireJoined` 失败 | 先连接，等「已加入房间」 |
| 消息解析失败 | `statusLine`「消息解析失败」 | 非 JSON | 重连；查中继版本 |
| 缺少 planId | Toast | 路由参数缺失 | 从「选择训练计划」进入 |
| 训练项为空 | Toast | 计划下无项目 | 到编排页添加项目 |
| 加载计划失败 | Toast `e.message` | HTTP 拉计划失败 | 查 plan-project/material 接口 |
| 计划已下发 | Toast 成功 | `setPlan` 已发送 | 大屏应收到 `state` |

### 4.2 中继 WebSocket 错误码（`relay-server`）

服务端消息格式：

```json
{ "type": "error", "code": "<错误码>", "message": "<中文说明>" }
```

| code | message（典型） | 含义 | 处理 |
|------|----------------|------|------|
| `bad_join` | 房间号与令牌均为4位数字 / 缺少房间号或令牌 | join 参数不合法 | 改为 4 位数字；mobile 必须带 roomId+token |
| `unauthorized` | 房间不存在或令牌错误，请先启动大屏… | 房间/令牌不匹配，或**旧版中继** | 核对凭证；部署新版 relay（见 §5） |
| `unauthorized` | 房间号已占用且令牌不匹配 | 已有房间 token 不同 | 统一为预置 `1001`/`2002` 或大屏显示的 token |
| `already_joined` | 已加入房间 | 重复 join | 忽略，直接发 command |
| `not_joined` | 未加入房间 | 未 join 就发 command | 先 join |
| `room_missing` | 房间已失效 | 房间被清理（固定房间除外） | 重新 join；`1001` 常驻 |
| `bad_command` | 未知命令 | 命令名或 payload 非法 | 「刷新计划」；升级客户端与中继 |
| `bad_json` | 无效 JSON | 报文损坏 | 重连 |
| `join_timeout` | 连接超时，请先发送 join | 15s 内未 join | 连接后立即发 join |
| `bad_role` | 未知角色: … | role 非 display/mobile | 检查 join 报文 |

教师端对 `unauthorized` 的 `statusLine` 固定为：「房间号或令牌错误，请核对4位数字」。

### 4.3 成功消息

| type | 含义 | 教师端行为 |
|------|------|-----------|
| `joined` | 加入成功，含 `roomId`、`token`、`state` | `statusLine`→「已加入房间」；自动 `setMediaAuth`；约 80ms 后 `pushSetPlan` |
| `state` | 房间状态广播 | 同步 `videoPlaying`、计划项索引等 |

### 4.4 教师端恢复操作（内置能力）

| 操作 | 作用 |
|------|------|
| 点「连接」 | `closeSocketTask` → `startConnect` → join(mobile) |
| 点「探测中继」 | HTTP 请求 `/relay-info` 验证可达 |
| 点「刷新计划」 | 重新 HTTP 拉计划并 `setPlan` |
| `onReady` 自动连接 | 满足 `canAutoConnect()` 时约 300ms 后自动连接 |
| 离开页面 `onUnload` | 关闭 socket，重置连接状态 |

**最小恢复路径（上课不同步）**：

```
教师端：连接 → 等「已加入房间」→ 刷新计划
大屏：顶栏「重试」
仍异常：核对两端 WS 地址、房间 1001 / 令牌 2002
```

## 5. 中继部署与运维（relay-server）

### 5.1 版本判定

| 检测 | 本机 `127.0.0.1:3456` | 机房 `10.112.189.54:3456` |
|------|----------------------|---------------------------|
| `npm run verify` | OK | — |
| `npm run verify:remote` | — | 应为 OK；FAIL 表示旧版 WS |
| `/relay-info` | `"protocol":2`, `"build":"relay-2026-v2"` | 同左 |
| 旧版 join 文案 | — | 「房间不存在或令牌错误」（**无**「请先启动大屏…」后缀） |

常见误区：

1. 本机 relay-info 正常 ≠ 机房已更新  
2. HTTP `/relay-info` 正常 ≠ WS 已更新（须 `verify:remote`）  
3. 大屏连本机、教师连机房 → 两个中继，无法同步  

### 5.2 机房标准重启

在 **10.112.189.54** 上执行（非开发机 `npm run dev`）：

```powershell
netstat -ano | findstr :3456
taskkill /PID <旧PID> /F

cd <relay-server 在服务器上的路径>
npm install
npm run build
npm start
```

成功日志须含：

```text
[relay] relay-2026-v2 protocol v2 pinned room 1001/2002
[relay] WebSocket listening on 0.0.0.0:3456
```

服务器验证：

```powershell
curl http://127.0.0.1:3456/relay-info
cd relay-server
npm run verify
```

开发机验证机房：

```bash
npm run verify:remote
```

部署成功后，将 `gym_screen` 的 `VITE_RELAY_WS` 改为 `ws://10.112.189.54:3456` 并重启 Vite。

### 5.3 本机联调

1. `cd relay-server && npm run dev`  
2. `gym_screen` 使用 `VITE_RELAY_WS=ws://127.0.0.1:3456`  
3. 教师 H5 用 `http://localhost:5174`（自动连 `ws://localhost:3456`）  
4. **勿**用机房 IP 打开教师端以免连到旧中继  

### 5.4 verify 脚本输出

| 输出 | 含义 | 处理 |
|------|------|------|
| `[verify] OK 新版 join 成功` | WS join(display) 1001/2002 成功 | 正常 |
| `[verify] FAIL 仍是旧版 WS` | unauthorized，旧程序 | 按 §5.2 部署 |
| `[verify] 超时` / `WS 错误` | 端口未监听或网络问题 | 启动 relay；查防火墙 |

## 6. 视频媒体代理（`/media-proxy`）

| HTTP | 响应体 / 头 | 含义 | 处理 |
|------|------------|------|------|
| 400 | `missing url` | 缺 `url` 参数 | 检查计划项 `videoUrl`/`imageUrl` |
| 401 | JSON `code:401`, `X-Relay-Error: missing-token` | 无 JWT | 教师端重连（自动 `setMediaAuth`）；勿 localhost 测远端房间 |
| 502 | JSON `code:502`, `source:upstream`, `X-Relay-Tried` | 后台未返回媒体流 | 配置 `/plan-materials` 静态访问或 download 接口 |
| 502 | 纯文本 `media proxy error` | 代理内部异常 | 看中继日志 `[relay] media-proxy error`；重启 relay |

上游失败详情格式示例：`code=401 msg=…`（JSON 响应被解析后拼入 `msg`）。

**大屏「教学内容加载失败」恢复**：

1. 教师端断开重连 → `setMediaAuth` + `setPlan`  
2. 点「刷新计划」  
3. 切换训练项再切回  
4. 仍失败 → 资料管理重传视频，确认 URL 可被后台访问

## 7. 训练大屏（gym_screen）

| 故障 | 输出形式 | 含义 | 处理 |
|------|---------|------|------|
| 连接中 | 顶栏「连接中…」 | WS 握手中 | 等待或点重试 |
| unauthorized（旧版） | `lastError` 含部署提示文案 | 机房 WS 旧版 | §5.2 部署；DEV 下**自动 FALLBACK** 本机 `127.0.0.1:3456` |
| unauthorized（凭证） | `lastError` + 房间/令牌提示 | 房间令牌错误 | 使用大屏显示的 room/token |
| HTTP 新 WS 旧 | `lastError` 专门提示 | 多进程/旧 WS 未杀净 | 杀净 3456 进程后 rebuild |
| WebSocket 错误 | `lastError`「WebSocket 错误」 | 网络/服务异常 | 点「重试」（`relay.connect()`） |
| 无效中继消息 | `lastError`「无效中继消息」 | 非 JSON | 重连 |
| 连接关闭 | `connectionPhase: closed` | 正常或异常断开 | 点「重试」 |
| 无教学资料 | 占位「等待教师端下发教学资料」 | 未 setPlan 或计划无媒体 | 教师端刷新计划 |
| 视频/图片加载失败 | 遮罩「教学内容加载失败」 | media-proxy 或 URL 无效 | 见 §6 |
| overlayError | 遮罩「错误高亮占位」 | 教师端 toggled 调试叠加 | 教师端关闭或忽略 |
| overlaySkeleton | 遮罩「骨骼线占位」 | 调试叠加 | 同上 |
| 复制失败 | 调试日志 COPY | 剪贴板权限 | 手动抄写房间号/令牌 |

连接成功后顶栏提示：`小程序遥控 WS：… · 房间 xxx / 令牌 xxx` — 教师端应使用相同 WS 与凭证。

## 8. 考核流程

| 阶段 | 故障 | 输出 | 处理 |
|------|------|------|------|
| exam-setup | 缺少课程/班级/课堂 | Toast「请返回重试」 | `navigateBack` 从班级详情重进 |
| exam-setup | 未选考核项目 | Toast | 选择落点或动作识别 |
| exam-session | 班级ID无效 | Toast | 检查路由 `classId` |
| exam-session | 获取学员失败 | Toast `msg` /「网络连接异常」 | 重进；后台添加学员 |
| exam-session | 参数缺失 / 未选学员 | Toast | 补全流程 |
| exam-active | 参数不完整 | Toast「请返回重试」 | 从 exam-setup 重走 |
| exam-active | 落点检测 | Toast「识别服务开发中」 | 占位；换动作识别或等待接口 |
| exam-active | 非动作识别项测视频 | Toast | 仅动作识别支持相册视频 |
| exam-active | 选视频失败 / 无文件 | Toast | 重新选择相册视频（≤300s） |
| exam-active | 上传识别失败 | Toast `e.message` | 查 `10.101.166.129:8000`；重传 |
| exam-active | 已提交分析任务 | Toast 成功 | 记录 `requestId`/`status` |
| exam-active | 启动/结束失败 | Toast | `stopRecognition` 为占位，可退出页面 |

动作识别服务内部错误：

| Error message | 含义 | 处理 |
|---------------|------|------|
| 缺少视频文件路径 | 未传 filePath | 先选视频 |
| 动作识别服务返回数据解析失败 | 响应非 JSON | 查算法服务 |
| 动作识别服务返回格式不支持 | 响应类型异常 | 查算法服务 |
| 动作识别服务返回缺少 request_id 或 status | 响应字段不全 | 查算法 API 契约 |

## 10. 场景化快速恢复

### 场景 A：上课中途大屏不同步

```
教师端：连接 → 「已加入房间」→ 刷新计划
大屏：重试
核对：同一 WS 地址、房间 1001、令牌 2002
```

### 场景 B：有连接无视频

```
教师端重连（setMediaAuth）→ 刷新计划
查中继 media-proxy 日志与后台 plan-materials
```

### 场景 C：整节课无法遥控（机房）

```
服务器杀 3456 旧进程 → npm run build && npm start
verify:remote 通过后再开大屏和教师端
```

### 场景 D：登录后全部接口失败

```
退出登录 → 重新登录
仍失败：查 admin-api 与网络
```

### 场景 E：创建训练项目失败一半

```
进「训练项目编排」检查半成品
删除多余项或补传资料；避免重复点击创建
```

## 11. 内置能力 vs 需人工

## 12. 现场检查清单（约 2 分钟）

1. `curl http://<中继IP>:3456/relay-info` → `protocol: 2`，`build: relay-2026-v2`  
2. `npm run verify:remote` → OK  
3. 大屏顶栏无红字，或重试已成功  
4. 教师端 `statusLine`：「已加入房间」  
5. 大屏与教师端房间/令牌一致（默认 1001/2002）  
6. 教师端已「刷新计划」，日志有 `setPlan`  
7. 视频问题：日志 `token=有`、`video=有`；仍失败查 §6
